# Tilo 核心概念与设计模型 (Concepts)

> English version → [../en/CONCEPTS.md](../en/CONCEPTS.md)

Tilo 建立在严格、清晰且符合个人真实执行规律的领域模型之上。理解这些概念将帮助你更好地使用 Tilo 构建自己的时间与执行闭环。

---

## 1. 核心层级模型 (Core Execution Hierarchy)

Tilo 的执行领域模型采用严格的五层分级结构：

```text
Goal (目标)
  ↓
Project (项目)
  ↓
Task (任务)
  ↓
Subtask (子任务 - 严格单层)
  ↓
Session (执行时段 / 会话)
```

### 1.1 Goal (目标)
- **定义**：长期追求的战略方向、里程碑结果或持续维持的重点领域。
- **特性**：支持以任务完成率自动聚合进度，或通过自定义量化指标 (Metric) / 持续进行 (Ongoing) 进行跟踪。

### 1.2 Project (项目)
- **定义**：为了达成某个阶段性目标而聚合的一组结构化工作。
- **特性**：
  - 可以归属于 1 个主目标 (`Primary Goal`)；
  - 可以关联多个辅助目标 (`Related Goals`)；
  - 也可以完全作为独立项目存在（无目标绑定）。

### 1.3 Task (任务)
- **定义**：具有明确完成标准的具体工作单元。
- **特性**：可以属于某个项目，也可以作为独立任务存在。每个任务拥有预估耗时、截止日期、安排执行日期与工作流状态。

### 1.4 Subtask (子任务)
- **定义**：父任务内部的单层拆分步骤。
- **重要约束**：Tilo 严格限制**子任务仅允许一层深度**，不支持无限嵌套。子任务可以单独设定安排日期并启动专注计时。

### 1.5 Session (执行时段)
- **定义**：一段真实发生且被记录的专注时间片。

## 2. 关键概念辨析 (Critical Distinctions)

### 2.1 任务不等于执行时段 (Task ≠ Session)

任务描述的是**“要达成的产出”**，而 Session 记录的是**“实际投入的时间”**。一个任务往往需要多次专注才能完成：

```text
Task: 完成毕业论文第三章实验撰写
  ├─ Session 1 (周一 09:30–10:15): 45 分钟
  ├─ Session 2 (周二 14:00–15:20): 1 小时 20 分钟
  └─ Session 3 (周三 16:00–16:55): 55 分钟 (完成任务)
```

### 2.2 截止日期 vs 安排日期 (Due Date vs Scheduled Date)
- **Due Date (截止日期)**：该任务最晚必须在何时交付（客观 Deadline）。
- **Scheduled Date (安排日期)**：你计划在哪一天着手处理该任务。

> **示例**：论文报告在 8 月 30 日截止 (Due)，但你将它安排在 8 月 22 日处理 (Scheduled)。

### 2.3 安排日期 vs 计划时间块 (Scheduled Date vs Planned Block)
- **Scheduled Date**：粗粒度的时间承诺（“我周五要做这事”）。
- **Planned Block**：细粒度的时间轴预留（“我周五 14:00–15:30 在时间轴上预留 90 分钟做这事”）。

### 2.4 计划与实际 (Plan vs Actual)
- **Plan (计划)**：事前设想的时间安排，在日历与时间轴上以**半透明虚线框 (Ghost Block)** 呈现。
- **Actual (实际)**：事后真实发生的专注记录，在时间轴上以**实色块 (Solid Block)** 呈现。
- 两者并存使系统能够呈现真实的执行偏差，而不是在执行后抹掉原本的计划。

### 2.5 预估耗时 vs 计划时长 vs 实际时长 (Estimate vs Planned vs Actual Time)
- **Estimate (预估耗时)**：对任务总体需要投入的总工作量评估（例如：90 分钟）。
- **Planned Time (计划时长)**：在时间轴上分配给该时间块的跨度（例如：14:00–15:30，共 90 分钟）。
- **Actual Time (实际时长)**：该任务关联的所有活跃 Session 的有效专注总和（排除暂停时长）。

### 2.6 任务 vs 专注时间块 (Task vs Focus Block)
- **Task**：具体的待办事项。
- **Focus Block**：在日历中为某类工作预留的**时间预算**（例如：上午 09:00–11:00 预留为“深度工作 (Deep Work)”时间块）。Focus Block 本身不是一个具体的任务，但可以容纳任务在其时间段内执行。

### 2.7 收件箱 vs 择日 (Inbox vs Someday)
- **Inbox (收件箱)**：处于未分流状态的即时捕获内容（想法、链接、临时待办），等待整理。
- **Someday (择日)**：经过筛选确认有价值、但近期没有明确时间承诺的待办储备池。

### 2.8 前台有效专注 vs 后台会话 (Active Session vs Background Session)
- **Active Session**：占用用户核心注意力的高强度专注。计时器中暂停 (Pause) 的时间段会自动剔除，仅统计净有效时长。
- **Background Session**：后台静默进行的操作或长时任务（例如：跑批处理模型）。在 Analytics 中单独统计，**不膨胀**核心活跃专注时间 (Active Time)。

### 2.9 每日聚焦 vs 每周焦点 (Today Focus vs Weekly Focus)
- **Today Focus**：今天最优先推进的 1–3 项核心任务（Rank #1, #2, #3）。
- **Weekly Focus**：本周战略层面重点推进的 Goal 目标徽章。

### 2.10 每日容量 (Daily Capacity)
- **定义**：用户为某一天设定的可支配专注时间上限（默认工作日 8 小时，周末 4 小时）。
- **设计原则**：Daily Capacity 是一种**时间预算边界提示**，而非强制配额。超额规划时系统会以温和的指标提示超额，但绝不阻止用户的自由安排。

### 2.11 历史快照与不可变性 (Snapshot & Immutability)
- **定义**：在完成每日收尾 (Daily Close) 或每周复盘 (Weekly Review) 时封存的周期执行快照。
- **不可变原则**：已封存的快照数据严格只读。如果后续对过去的某个任务进行了编辑或删除，历史快照依然保持封存时的原貌，确保历史审计的真实性。

## 3. 中英文术语对照表 (Terminology Glossary)

| 英文术语 (English) | 简体中文 (zh-CN) | 说明 / 语义定义 |
| :--- | :--- | :--- |
| **Goal** | 目标 | 长期战略方向或核心指标 |
| **Project** | 项目 | 阶段性工作容器，可关联主目标与相关目标 |
| **Task** | 任务 | 具有完成状态的具体工作单位 |
| **Subtask** | 子任务 | 任务下属的严格单层子项 |
| **Session** | 执行时段 / 会话 | 一次真实的专注执行记录 |
| **Planned Block** | 计划时间块 | 在时间轴上预留的计划时段（幽灵态虚线框） |
| **Focus Block** | 专注块 / 时间预算 | 为某种工作类型预留的日历时间预算 |
| **Plan vs Actual** | 计划与实绩 | 计划安排与真实执行的对比分析体系 |
| **Daily Focus** | 今日聚焦 | 每日核心优先任务清单（1–N 排位） |
| **Weekly Focus** | 本周焦点 | 本周重点推进的核心战略目标 |
| **Next Up** | 下一步建议 | 基于排期与优先级的单项客观行动推荐 |
| **Daily Capacity** | 每日容量 | 单日可用时间预算（工作日/周末可独立配置） |
| **Daily Close** | 每日收尾 | 每日工作结束时的任务整理与快照封存 |
| **Weekly Review** | 每周复盘 | 结构化周度回顾与下周规划工作流 |
| **Review Revision** | 复盘修订版次 | 不可变复盘快照的版次序号（如 revision 1, 2） |
| **Instant Capture** | 即时捕获 | 低摩擦全局灵感与待办快速收集机制 |
| **Inspector** | 检视器 | 右侧通用详情查看与快速编辑面板 |
| **Command Menu** | 命令菜单 | 全局 `Ctrl+K` 快速导航与操作指令中心 |
| **Unplanned Work** | 临时插入工作 | 未在时间轴上预先排期的非计划专注投入 |
